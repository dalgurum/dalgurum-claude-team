# Feature Extractor Skill

`plan.md`를 입력으로 받아 에이전트 팀 3개가 기능 목록을 추출하고 기술 환경을 제안한다.
출력은 사람용 상세 버전과 다음 스킬(`design-discussion`)용 요약 버전으로 분리한다.

---

## 1단계: plan.md 로드

작업 디렉토리에서 `plan.md`를 읽는다.
파일이 없으면 사용자에게 `plan-enhancer` 스킬 먼저 실행을 안내하고 중단한다.

---

## 2단계: 에이전트 팀 병렬 분석

아래 3개 에이전트 팀에게 `plan.md` 전문을 전달하고 각각의 관점으로 분석을 요청한다.

### architecture-team 에게 요청할 것
- 시스템 구성 관점에서 필요한 기능 목록
- 각 기능의 기술적 복잡도 (상/중/하)
- 서비스 간 의존관계
- 추천 기술 스택 및 근거

### ux-flow-team 에게 요청할 것
- 사용자 여정 관점에서 필요한 기능 목록
- 각 기능의 사용자 접점 (화면, API 엔드포인트)
- 누락된 UX 흐름

### devil-advocate-team 에게 요청할 것
- 기획에서 과도하게 복잡하거나 불필요한 기능
- 초기 버전에서 제외해도 되는 기능 (MVP 관점)
- 기술적으로 구현이 어렵거나 리스크가 높은 기능

---

## 3단계: Claude 종합

3개 팀의 분석 결과를 종합하여 최종 기능 목록을 확정한다.

### 종합 기준
- 3개 팀 모두 필요하다고 판단한 기능: **필수**
- 2개 팀이 필요하다고 판단한 기능: **권장**
- devil-advocate-team이 제거를 권고한 기능: **검토 후 결정**

---

## 4단계: 출력 파일 생성

### features.md (사람용 상세 버전)

```markdown
# 기능 목록

## 필수 기능
| 기능명 | 설명 | 복잡도 | 담당 레이어 |
|---|---|---|---|

## 권장 기능
| 기능명 | 설명 | 복잡도 | 담당 레이어 |
|---|---|---|---|

## 보류 기능 (devil-advocate 검토 의견)
| 기능명 | 제외 근거 | 재검토 조건 |
|---|---|---|

## 에이전트 팀별 분석 원문
### architecture-team 의견
### ux-flow-team 의견
### devil-advocate-team 의견
```

### features.summary.md (다음 단계용 요약 버전)

```markdown
# 기능 요약 (design-discussion 입력용)

## 필수 기능 목록
- [기능명]: [한 줄 설명] / 복잡도: [상/중/하] / 레이어: [백엔드/프론트/인프라]

## 권장 기능 목록
- [기능명]: [한 줄 설명] / 복잡도: [상/중/하] / 레이어: [백엔드/프론트/인프라]
```

### stack.md (사람용 상세 버전)

```markdown
# 기술 환경 제안

## 백엔드
- 프레임워크: [제안] / 근거: [설명]
- 데이터베이스: [제안] / 근거: [설명]

## 프론트엔드
- 프레임워크: [제안] / 근거: [설명]

## 인프라
- CSP: [제안] / 근거: [설명]
- 주요 서비스: [목록]

## 기술 선택 시 검토한 대안
```

### stack.summary.md (다음 단계용 요약 버전)

```markdown
# 기술 스택 요약 (design-discussion 입력용)

- 백엔드: [스택]
- 프론트엔드: [스택]
- 인프라: [CSP + 주요 서비스]
- DB: [스택]
```

---

## 주의사항

- 기능은 구현 단위가 아닌 사용자 가치 단위로 정의한다
- 담당 레이어(백엔드/프론트/인프라)를 반드시 명시한다
- 출력 후 사용자에게 `design-discussion` 스킬로 다음 단계 진행 가능함을 안내한다
