# Plan Enhancer Skill

사용자가 제공한 기획안을 전문 기획자 시선으로 분석하고 보완하여 `plan.md`를 생성한다.
이 파일은 이후 `feature-extractor` 스킬의 입력으로 사용된다.

---

## 1단계: 기획안 분석

아래 항목 기준으로 제공된 기획안을 평가한다.

### 반드시 확인할 항목
- **서비스 목적** — 이 서비스가 존재하는 이유, 해결하는 문제
- **타겟 사용자** — 누가 사용하는지, 사용자 특성
- **핵심 기능** — 서비스의 핵심 가치를 전달하는 기능
- **사용자 시나리오** — 사용자가 어떤 흐름으로 서비스를 이용하는지
- **비기능 요구사항** — 성능, 보안, 확장성 등
- **제약 조건** — 기술적/비즈니스적 제약
- **성공 지표** — 이 서비스가 성공했다고 판단하는 기준

### 보완이 필요한 경우 추가할 항목
- 경쟁 서비스 대비 차별점
- 예외 케이스 및 엣지 케이스
- 데이터 관리 정책 (보존, 삭제, 백업)
- 운영/관리자 기능 필요 여부

---

## 2단계: 보완 작업

분석 결과를 바탕으로 아래 기준으로 기획안을 보완한다.

- **누락된 항목**: 위 체크리스트에서 빠진 내용을 추가한다
- **모호한 표현**: 구체적인 수치나 조건으로 명확하게 재작성한다
- **논리적 모순**: 기획 내에서 충돌하는 내용을 발견하면 수정 의견을 제시한다
- **실현 가능성**: 기술적으로 불가능하거나 과도한 요구사항은 현실적인 대안을 제시한다

---

## 3단계: plan.md 출력

작업 디렉토리 루트에 `plan.md`를 생성한다.

### plan.md 구조

```markdown
# [서비스명] 기획서

## 1. 서비스 개요
- 서비스 목적
- 핵심 가치 제안
- 타겟 사용자

## 2. 핵심 기능 목록
- 기능명: 설명 (우선순위: 상/중/하)

## 3. 사용자 시나리오
- 주요 사용 흐름 (Happy Path)
- 예외 케이스

## 4. 비기능 요구사항
- 성능 목표
- 보안 요구사항
- 확장성 고려사항

## 5. 제약 조건
- 기술적 제약
- 비즈니스 제약

## 6. 성공 지표 (KPI)

## 7. 기획 보완 내역
- [보완 항목]: 원본에서 추가/수정한 내용과 이유
```

---

## 주의사항

- 원본 기획 의도를 훼손하지 않는다
- 보완한 내용은 반드시 `## 7. 기획 보완 내역`에 기록한다
- 기술 스택은 이 단계에서 결정하지 않는다 (다음 스킬에서 처리)
- 출력 후 사용자에게 `feature-extractor` 스킬로 다음 단계 진행 가능함을 안내한다
